# Reference UI 254

Implements the layout of docs/ui-193 as real interface code, not image backgrounds. The default desktop shell uses a large vector DS shield, vertical navigation with a red active stripe, visible page heading, camera/events columns and real telemetry summary cards. Controls use a camera/device split, mode tiles retaining their original actions and a full-width recording action bar. Settings place categories left, real inputs in the centre and help right on wide screens. Diagnostics add scalable component icons and retain actual store states. Archive controls move above the playback viewport through layout only; the timeline, recording actions and real storage panel remain owned by their existing modules. Mobile navigation uses matching vector icons, dark cards and red active state while retaining orientation/PiP behaviour. Account and PIN presentation use the same palette.

No scene photos or sample files from concept images are used as live camera data. Existing five system modes are retained; unsupported object recognition, sensor hardware and camera controls are not fabricated. No camera, PIN, OAuth credentials or user recordings are reset.

Validation: 362 frontend tests; isolated Chrome production-markup checks for all six routed desktop views at 1024/1440/1920, same live video node and synthetic media track retained, summary visibility and collapse to 72px. Mobile frame/layout regression has 30 passing cases. Windows compilation passed with one existing WindowsBase reference warning. Public links: 23 documents/98 destinations. These checks are not a claim of physical camera recording or of installation on the user PC; installed version and public package are verified separately during deployment.
